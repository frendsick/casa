## Inputs and provenance

The control is the compiler built from `29fe1866a6ed6e408bdf127b19bf3734b839e376`
using the configured stable v1.50.0 bootstrap compiler. The candidate is the
captured Python prototype packaged as an executable archive. The raw report's
`source_commit` is the control/base revision. Candidate source hashes identify
the working files measured before this evidence commit.

- Machine: AMD Ryzen 7 3700X, 16 online logical CPUs, Linux x86-64 under WSL2.
- Python: 3.14.7. Native driver: Ubuntu GCC 11.4.0. Full platform strings are in the raw report.
- Bootstrap SHA-256: `fc01ea17cd20c48bb6e5de9df2612f7d104ac2f5b17357485eb6f0c9fa459e69`.
- Control and executable-archive SHA-256 values are in the raw report.

Commands run from the worktree root:

```sh
./casac -L lib casa.casa -o /tmp/casa-651-control
python3 compiler/blueprint_prototype/run.py --control /tmp/casa-651-control
git diff --check
```

The harness builds the shared native fixture with `cc` and `ar`. Both compilers
use identical source, library inputs, `--keep-asm`, and output paths for each
measurement pair. Each workload has one warm-up followed by three alternating
control/candidate pairs. Wall time includes compiler startup and native tools.
Peak RSS comes from `/usr/bin/time`. The final run had no failed workloads.
Earlier development runs found and corrected ownership and scope defects, then
physical storage and return-stack behavior were extended before fresh review.
The final run also corrects the snapshot footprint counter to include record
dictionaries. Earlier samples are not pooled with these final samples.

## Independent editor products

After 150 warm-up analyses, the harness replaces a snapshot 120 times while
retaining its predecessor during each replacement. It performs one hover query
per edit. A separate untraced 120-request loop measures latency.

- Analysis plus query: median 1.133 ms, range 1.090 to 1.330 ms.
- Unique reachable field objects plus record dictionaries: 21,344 bytes at each of six 20-request samples. Class metadata is excluded.
- Traced retained allocations at the six samples: 16,506, 17,463, 18,326, 18,907, 19,582, 20,210 bytes.
- Traced peak: 167,743 bytes. After releasing both snapshot references: 4,475 bytes.

The fixed reachable size supports bounded snapshot contents for this workload.
Traced retained allocations still grow during the run. This does not prove a
process-memory plateau or cover long-running workspace behavior. Graph counting
materializes Python record dictionaries, so traced end-of-run allocations also
include that measurement effect. Snapshot contents contain no compiler bodies.
The harness checks that an owned query answer survives release of its snapshot.

## Maintenance calibration and limits

The candidate has 1,408 compiler lines and 592 embedded-runtime lines. The harness
has 366 lines, with 120 fixture lines across Casa and C. Count runtime text as
maintained source. Reports and the generated HTML are evidence artifacts.
No production lines have been removed by this experiment.

The pinned audit's non-overlapping opportunity remains 820 to 850 production
lines and 350 to 500 test lines. Approximately 500 runtime lines were identified
for relocation, which is not deletion. The slice does not justify scaling its
line count to the full compiler or adding the overlapping opportunities listed
in the blueprint. Larger maintenance gains remain an implementation hypothesis.

The exercised boundary removes caller coordination of compiler phases and
operation/store pairing. The editor product retains source facts and exact
source text independently of checking and emission. Three entry operations and
two queries are exercised. The accepted production interface has five queries.

There is no paired self-compilation result because the prototype is not a
self-hosted Casa compiler. Full language and ABI coverage, workspace behavior,
self-hosting, fixed point, and measured production maintenance gains remain
implementation gates. Future time and peak-RSS budgets require an explicit
maintainer decision. These Python measurements cannot supply a native forecast.
